## Work completed

- All projects are SDK-style, targeting `net10.0-windows`. They keep their assembly names, root namespaces, `Properties\AssemblyInfo.cs` files and WPF `Resource` items. The solution file is `WireFlow.slnx`.
- NuGet packages are `PackageReference` items: Newtonsoft.Json 13.0.4, Microsoft.Data.Sqlite 10.0.14, and Optimax's own MaxServices.Core 1.1.0 and OptimaxTools.Options 1.0.0 from `LocalPackages\`. `THIRD-PARTY-NOTICES.md` holds the third-party license texts.
- Property grid: `OptimaxTools.Wpf.PropertyGrid` (new project) replaces Extended.Wpf.Toolkit's, which is gone. Categories or names, filter, header, resizable name column, virtualized rows; editors chosen by `PropertyEditors`, a registry like Delphi's `RegisterPropertyEditor`; `PropertyValueChanged` only for edits made in the grid (see "Property grid" in `implementation.md`). An editor can have a dialog, opened by a "…" button at the right end of the value or Ctrl+Enter; the Designer's `ColorPropertyEditor` opens `ColorPickerDialog` (PixiEditor.ColorPicker 3.4.2.3, as in MarkdownTools and PDFTools) for every brush and color.
- Docking: `OptimaxTools.Dock`, `OptimaxTools.Dock.Core` and `OptimaxTools.Dock.Themes.Metro` are the renamed source of Dirkster.AvalonDock 5.0.1 (see the shared projects in `implementation.md`).
- Compact lists: the rows of Tools, Pages, Layouts, Parts, Images and History are 27 px tall in the Fluent themes, as a menu item, rather than 45 px, through a local `Padding` on each row; Classic keeps its own 23 px rows (see "Themes" in `implementation.md`).
- Default page background: a new project's pages are `#555` (`FlowProject.DEFAULT_BACKGROUND`), instead of `#333`, which is the area around the page in Dark. Existing projects keep the background they have.
- Page frame: `DesignerPanel` draws a 1 px frame in the palette's `PageFrame` just outside the page, at its zoomed and panned bounds, so the page shows when its color is the theme's `PreviewBackground` (`#333333` in Dark, the samples' page color).
- Splitters: the splitters between panes are a rail with 1 px borders in the palette's `ChromeBorder`, inside their 5 px grab area. They now get the Metro theme's splitter style at all: `LayoutGridControl.CreateSplitters` used to give them a null `Style`.
- `Directory.Build.props` stops the SDK from generating the attributes the `AssemblyInfo.cs` files already declare.
- `publish-locally.bat` publishes the 64-bit Designer, built in Release mode, framework-dependent, to `c:\Programs\Optimax\WireFlow`.
- Outline Sync: `DesignerNavigator` raises `ElementsChanged` after it creates, duplicates, deletes, groups, ungroups or reorders elements. `MainDesignerWindow` rebuilds the outline when the event comes from the current designer.
- Application icons: the Designer has the WF logo as a square icon (white on red), the Browser a variation (red on charcoal with a gray rim). `Documents\make-icons.ps1` generates both at 16, 20, 24, 32, 40, 48, 64 and 256 px.
- Properties pane: the grid takes the theme's colors from `ListBackgroundBrush`, `LightLightColorBrush` and `DarkDarkDarkBrush` (category headers), set in `MainDesignerWindow.xaml`.
- `publish-locally.bat` empties the publish folder before publishing.
- Themes: the Designer has View → Theme (System, Light, Dark, Classic) through `MaxServices.Core` 1.1.0's `AppTheme`, as in PDFTools; `DesignerTheme` maps the Designer's brush keys and the Metro theme's base colors to the palette (see "Themes" in `implementation.md`).
- `.wf` project files: `SqliteRepository` (new `WireFlow.Repository.Sqlite` project) keeps a project in one SQLite file and is the storage of both programs; the Designer converts a `.project` it opens into a `.wf` beside it (see "Project file format" in `implementation.md`).
- Browser themes: the same View → Theme menu, kept in `BrowserSettings` (`%APPDATA%\WireFlow\WireFlow.Browser.config`). The Infragistics MetroDark theme and package are gone.
- Tools → Options: `DesignerOptionsDialog`, on MarkdownTools' and PDFTools' shared Options dialog (`OptimaxTools.Options` 1.0.0), with one group, Files, and one option, "Reopen the previous project at startup" (see "Options" in `implementation.md`).
- Tool glyphs: each tool in the Tools list has a line glyph before its title, from an SVG in `WireFlow.Designer/Glyphs` converted once into `Xaml/ToolGlyphs.xaml` by `Documents/make-tool-glyphs.cs` (see "Tool glyphs" in `implementation.md`).
- `.wf` format 2: documents are written with `FlowJson.Settings`, without `$type` tags; an element's `Type` chooses its class, enums are written by name, NaN as `null`, and every value is written (see "Project file format" in `implementation.md`). The programs open format 2 only. Every `.wf` in `Data`, the untracked `FirstTest.wf` included, was upgraded once with `Documents\upgrade-wf-to-format-2.cs`. `GetPart` reads a part as `FlowPart`, so a part saved in the Designer reads back. A `.project` folder opened in the Designer is converted into format 2.
